0The shift in one paragraph

Power Automate got Oliver live — but it is a linear, low-code flow: one email in, a sequence of steps, one email out. The agentic mesh from the planning doc needs three things a flow can't give cleanly: parallel agents, shared state, and events (gates, stalls, drift) that fire between and after submissions. Azure provides all three as managed services. The plan is to keep the experience identical for submitters — they still just email Oliver — and move the brain onto Azure: Durable Functions orchestrating the agents, Azure OpenAI as the model layer, Cosmos DB as the living registry, Service Bus as the event bus, and a small authenticated Azure site where super-users and admins run tests, inspect agent reasoning, and approve the irreversible calls.

The one-line shift: the channel stays human-friendly (email), the engine becomes cloud-native and event-driven. Submitters notice nothing; the system gains a lifecycle.

1Design goals & constraints

GoalWhat it means concretely
Email-first for submitters The trigger and the reply stay email. Zero new UI for the ~everyday user. A shared mailbox (e.g. oliver@siemens-energy.com) is the front door; Herald sends the assessment back.
A site only for super-users & admins A secured Azure web app for the few who review, manually run/test assessments, tune weights, and confirm No-Go / scale / retire. Gated by Entra ID roles — submitters never see it.
Truly agentic, not a flow Agents run in parallel, share one registry, and react to events — not a fixed step sequence.
Governed by construction Managed identity everywhere, secrets in Key Vault, every score & decision logged, EU AI Act classification tracked. Oliver gates AI — so Oliver itself must be auditable.
Incremental & reversible Power Automate keeps running until Azure provably matches it. Shadow-run, compare, then cut over a cohort at a time. Rollback = re-point the mail trigger.
Re-use what works Keep the v3.0 prompts, the 0–100 evidence-mandatory scoring, the coaching ethos, the HTML email template. We change the plumbing, not the assessment logic.

2Power Automate today → Azure target

Where Oliver runs today

  • Outlook trigger in a Power Automate flow
  • Linear steps; agents simulated as sequential prompt calls
  • Tracker in SharePoint / Excel — manual snapshot
  • One pass per email; nothing happens after
  • Hard to parallelise, version, test, or observe

Where Oliver is going on Azure

  • Graph mail webhook → Function ingest (same email UX)
  • Durable Functions fan-out the assessment agents in parallel
  • Cosmos DB registry — live single source of truth
  • Service Bus events drive the lifecycle continuously
  • CI/CD, traces, and a test harness — engineering-grade

Same front door, a different — and far more capable — engine behind it.

4The two front doors

One system, two ways in. The everyday path is email and never changes. The privileged path is a site — and both hit the same Conductor and Registrar underneath.

Door A — the submitter (email, unchanged)

SubmitterEmails an idea/submission to oliver@… (with attachments).
Graph webhookChange notification fires → Azure Function picks up the message + attachments.
Ingest FunctionParses, stores attachments in Blob, writes a normalized Submission record to Cosmos, raises submission.received.
ConductorDurable orchestrator starts: DocGuard pre-gate → fan-out IdeaPulse / ValuePulse / TechScope / PathFinder in parallel.
Verdict + StageMasterConsolidate to one 0–100 score; assign DI stage & lifecycle state; IdeaCoach + Pacer attach coaching and cadence.
RegistrarPersists scores, evidence, state; appends to the audit log.
HeraldRenders the HTML assessment and sends the reply email via Graph. Submitter is done — no site, no login.

Door B — the super-user / admin (Azure site)

AdminSigns in to the Static Web App with Entra ID (SuperUser or Admin role required).
Portfolio viewReads the live registry: every pilot, its DI stage, state, score, days-to-next-gate, SLO health.
Run / testPastes or uploads a draft submission and triggers an assessment on demand — same agents, sandbox flag — to test prompts/weights before they go live.
InspectOpens any pilot to see per-agent scores, evidence, and the full reasoning trace (App Insights correlation id).
ApproveThe HITL queue surfaces irreversible calls (No-Go, scale, retire); the orchestrator is paused on a Durable wait-for-external-event until a human confirms.
TuneAdjusts scoring weights / thresholds (versioned in the registry) and re-runs trend-mining.
Why this split is the right one: 95% of users get the lowest-friction interface possible (their inbox), while the handful who operate and govern the system get the depth they need (traces, test harness, approvals) — without ever exposing that complexity to submitters.

6Orchestration & the event bus — turning a flow into a mesh

This is the heart of the agentic upgrade. Power Automate runs a fixed sequence; the Conductor runs on events, so the system keeps working between and after submissions.

The events that drive the lifecycle

submission.received gate.decided pilot.stalled slo.breached drift.detected value.checked pilot.retired

Each is a Service Bus topic. Agents subscribe to the ones they care about; the Conductor routes and the Registrar's Cosmos change feed turns state writes into more events. Two orchestration patterns carry most of the load:

  • Fan-out / fan-in — DocGuard passes, then the four assessment agents run in parallel; Verdict joins their results. (In Power Automate these were serial — this alone is a big latency win.)
  • Human interaction — for No-Go / scale / retire, the orchestrator pauses on a Durable wait-for-external-event and resumes only when an admin clicks approve in the console.
PSEUDOCODEConductor — the submission orchestratorDurable Functions sketch+ 
// Durable orchestrator — fan-out/fan-in + HITL, illustrative
function* assessSubmission(ctx) {
  const sub = ctx.getInput();

  // pre-gate: completeness
  const doc = yield ctx.callActivity("DocGuard", sub);
  if (doc.completeness < 30) return yield ctx.callActivity("Herald.coachingReject", doc);

  // fan-out the four assessors in parallel
  const [idea, value, tech, path] = yield ctx.Task.all([
    ctx.callActivity("IdeaPulse",  sub),
    ctx.callActivity("ValuePulse", sub),
    ctx.callActivity("TechScope",  sub),
    ctx.callActivity("PathFinder", sub),
  ]);

  // fan-in: consolidate + stage
  const verdict = yield ctx.callActivity("Verdict", { idea, value, tech, path });
  const stage   = yield ctx.callActivity("StageMaster", verdict);
  yield ctx.callActivity("Registrar.upsert", { sub, verdict, stage });

  // HITL only for irreversible calls
  if (stage.requiresHumanSignoff) {
    yield ctx.waitForExternalEvent("HumanDecision");  // admin console resumes this
  }

  const coach = yield ctx.callActivity("IdeaCoach", { sub, verdict, stage });
  yield ctx.callActivity("Herald.sendAssessment", { sub, verdict, stage, coach });
}

7Identity, security & governance

ConcernHow Azure handles it
Roles Entra ID app roles: Submitter (no site access — email only), SuperUser (run/test, inspect), Admin (approve, tune weights, govern). The SPA enforces via MSAL; the API re-checks every call.
Secrets Nothing in code or config. Key Vault holds keys/connection strings; every service uses a Managed Identity — no passwords to leak.
Network Private endpoints for Cosmos, OpenAI, Service Bus; APIM as the only public façade for the API; Front Door for the site.
Audit (Auditor) Every score and decision appended to an immutable Cosmos container + Log Analytics. The framework already requires a full audit trail — this makes it native.
EU AI Act Classification stored per pilot and re-checked as it evolves; Purview tracks data lineage. Oliver's own decisions are in scope — govern the governor.
Data residency Pin Azure OpenAI + storage to EU regions; submissions and transcripts never leave the tenant boundary.

9Migration off Power Automate — strangler-fig, not big-bang

Never flip a live governance system in one go. Wrap it, shadow it, prove it, then peel users across.

Keep PA livePower Automate stays the system of record while Azure is built. No disruption.
MirrorInbound mail is copied to the Azure ingest as well as PA — both process every submission.
Shadow-runAzure produces assessments silently; a diff harness compares score, stage, and coaching against PA. Tune until they match.
Cohort cutoverFlip Herald (the reply) to Azure for one pilot team; PA goes read-only for them. Watch.
Full cutoverExpand cohort to all; Azure becomes system of record; migrate the 20 tracked pilots into the registry.
RetireDecommission the PA flow once a full cycle runs clean on Azure. Rollback at any point = re-point the mail trigger.

10Observability, cost & scale

  • Observability. Every agent call is a traced span in App Insights with a per-submission correlation id — the admin trace viewer reads these. The audit trail is a by-product, not extra work.
  • Scale. Durable Functions and Container Apps scale to zero between submissions and fan out on demand — you pay for assessments, not idle capacity.
  • Token cost. The biggest variable is Azure OpenAI tokens × agents × submission. Route DocGuard and simple checks to a cheaper/smaller model; reserve GPT-4o for the scoring agents. Cache embeddings.
  • Guardrails. APIM rate-limits and budgets/alerts in Cost Management stop a runaway loop from becoming a runaway bill.

11Decisions to lock early

DecisionThe trade-off — and a lean recommendation
Agent framework AI Foundry Agent Service (managed, fastest to value) vs Container Apps + Semantic Kernel/AutoGen (more control/portability). Recommend: Foundry first; keep agents framework-light so a later swap is cheap.
State store Cosmos DB (scale, change feed, flexible schema) vs Dataverse (Power Platform governance, citizen-dev). Recommend: Cosmos as canonical; optional Dataverse read-view if PMO wants it.
Canonical scoring model Still the prerequisite from the planning doc: v3.0's 0–100 / 5-dim vs the tracker's 0–200 / 4-dim. Resolve before the Registrar schema is frozen — everything keys off it.
SAP access for Realizer Reconciling realized value needs read access to SAP PM/EWM/S4HANA. Longest-lead integration — start the access request in Phase 1 even though Realizer lands in Phase 4.
Mailbox identity Shared mailbox vs a service account for oliver@…; SPF/DKIM/DMARC so replies don't land in junk. Decide deliverability ownership early.
Build vs buy the site Static Web App SPA (full control) vs a Power Pages / low-code admin surface (faster, less flexible). For traces and a test harness, recommend the SPA.

12First sprint — start here

  1. Lock the canonical scoring model (v2 ↔ v3 reconciliation) — blocks the registry schema.
  2. Stand up the landing zone (Phase 0): IaC repo, Entra roles, Key Vault, Azure OpenAI in an EU region, green pipeline.
  3. Prove one agent end-to-end on Azure — port DocGuard to a Durable activity calling Azure OpenAI; email in → JSON out.
  4. Set up the shadow-run mirror so every PA submission is also seen by Azure from day one.
  5. Open the SAP access request for Realizer now — it's the longest pole.
  6. Spike the Static Web App shell with Entra login + an empty portfolio view, to de-risk Door B.
